Logic App Standard — Security Labs

Learn and implement proven security patterns for Azure Logic App Standard

Welcome

This repository contains three production-tested security patterns for Logic App Standard HTTP triggers. Each pattern solves a different business requirement:

  • Lab 1: Identity-Based Security with Easy Auth — Enforce Entra ID authentication while preserving Azure portal functionality
  • Lab 2: Centralized Gateway Security with APIM — Consolidate authentication across many Logic Apps using API Management
  • Lab 3: Service-to-Service Calls with Managed Identity — Enable secure app-to-app communication without managing secrets

Each lab includes complete infrastructure code (Bicep), step-by-step deployment instructions, testing procedures, and evidence collection methods.

The Three Security Patterns

🔐 Lab 1: Easy Auth & Identity

Enforce Entra ID authentication on Logic App HTTP triggers while keeping the Azure portal fully functional.

Tested & Validated ✅

🌐 Lab 2: Centralized Gateway with APIM

Consolidate JWT validation and access control at API Management instead of per-app configuration.

Tested & Validated ✅

🛡️ Lab 3: Secure Service Calls with Managed Identity

Enable Function Apps and other services to call Logic Apps using bearer tokens and automatic credential rotation.

Tested & Validated ✅
Lab 3 Highlight: Zero Secrets Architecture
Service-to-service authentication using managed identity bearer tokens — no SAS tokens, no shared secrets, automatic credential rotation. Complete Lab 3 Guide →
Network Efficiency
Traditional approach (many apps calling Logic App): 1000+ public IPs. With integrated security patterns: 1 IP.
Managed Connectors Are Unaffected Managed connectors (Office 365, SharePoint, file connector, etc.) are hosted by Microsoft in multitenant Azure and are NOT affected by VNet integration, APIM, or storage firewalls. They continue to work as normal.
