Overview

This page consolidates 6 findings discovered during lab validation. Two are Critical platform behaviours, two are Informational observations, and two are Resolutions that confirm working patterns.

Finding 1: Return401 Blocks hostruntime Critical

When authsettingsV2 is configured with unauthenticatedClientAction: Return401, all hostruntime-proxied management operations fail with HTTP 401.

Finding 2: ARM vs hostruntime Classification Informational

Logic App Standard has two classes of management endpoints. Understanding this classification is key to predicting Easy Auth behaviour.

Endpoint ClassAuthenticationEasy Auth Impact
ARM control-plane AAD token via ARM ✅ Unaffected — ARM authenticates independently
ARM workflow entity AAD token via ARM ✅ Unaffected — pure ARM operations
hostruntime data-plane Proxied to app host ❌ Intercepted by Easy Auth before runtime processes request

Even when called through management.azure.com, operations like listCallbackUrl are proxied to the app host by the ARM provider. Easy Auth intercepts the call at the host boundary.

Finding 3: excludedPaths Mitigates Blocking Informational

The excludedPaths property in authsettingsV2 can exempt management endpoints from Easy Auth while keeping trigger paths protected:

{
  "globalValidation": {
    "unauthenticatedClientAction": "Return401",
    "excludedPaths": [
      "/runtime/*",
      "/hostruntime/*"
    ]
  }
}
Details
ProsSurgical fix; trigger routes still require Entra token; single resource change; no extra infrastructure
ConsExcludes entire hostruntime path space; requires testing to confirm supported glob patterns; if Logic App serves other hostruntime paths that should be protected, additional controls needed
StatusDocumented — not yet validated in lab

Finding 4: Shared Key Policy Deadlock Critical

In subscriptions with Azure Policy enforcing allowSharedKeyAccess: false on all storage accounts, Logic App Standard cannot start its workflow runtime.

RequirementStatus
Logic App Standard needs AzureWebJobsStorage connection string✅ Required
Connection strings use storage account shared keys✅ Required by the runtime
Subscription policy enforces allowSharedKeyAccess: false🔴 Immediately reverts any attempt to enable shared keys
Result🔴 Logic App Standard workflow runtime returns 503 — cannot start

Impact: Customers enforcing allowSharedKeyAccess: false across subscriptions (common in enterprise security policies) cannot deploy Logic App Standard without a scoped policy exemption or waiting for Microsoft GA of managed identity host storage support.

Evidence:

  • az storage account update --allow-shared-key-access true exits 0 but value stays false
  • New storage accounts with allowSharedKeyAccess: true reverted within 15 seconds
  • AzureWebJobsStorage__accountName + managed identity setting results in runtime 503
  • GitHub Issue #1114 — managed identity storage support tracking

Finding 5: AllowAnonymous + allowedPrincipals Works Resolution ✅

Switching Lab 1 from Return401 to AllowAnonymous with allowedPrincipals set to the APIM managed identity resolves all portal manageability issues while maintaining trigger security.

Configuration

{
  "globalValidation": {
    "requireAuthentication": true,
    "unauthenticatedClientAction": "AllowAnonymous"
  },
  "identityProviders": {
    "azureActiveDirectory": {
      "validation": {
        "allowedAudiences": [
          "https://management.core.windows.net/",
          "https://management.azure.com/"
        ],
        "defaultAuthorizationPolicy": {
          "allowedPrincipals": {
            "identities": ["<APIM-managed-identity-principal-id>"]
          }
        }
      }
    }
  },
  "platform": { "enabled": true, "runtimeVersion": "~1" }
}

Key Insight: With AllowAnonymous, Easy Auth passes requests without an Authorization header directly to the runtime (where SAS key or other auth is required). Requests with an Authorization header are validated against Entra requirements (audience, principal, issuer). This means portal/ARM management calls pass through, while API calls with tokens are strictly validated.
